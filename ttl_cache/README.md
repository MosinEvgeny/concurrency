# Потокобезопасный TTL-кэш

## Задача

Для сервиса покупки автомобилей нужен потокобезопасный кэш с ограниченным временем жизни записей (TTL).
Реализуйте тип `TTLCache` с методами `Set`, `Get` и `Close`.
Фоновая очистка должна завершаться корректно, чтобы не допускать утечки горутин.

## Функциональные требования

- Реализуйте конструктор `NewTTLCache(ttl, cleanupInterval time.Duration) *TTLCache`.
- `Set(key, value string)` сохраняет значение и время истечения записи (текущее время + `ttl`).
- `Get(key string) (string, bool)` возвращает значение и `true`, если запись существует и не истекла. Для отсутствующей или просроченной записи верните пустую строку и `false`.
- Фоновая горутина периодически удаляет просроченные записи с интервалом `cleanupInterval`.
- `Close()` останавливает фоновую горутину и освобождает используемые ресурсы. Повторный вызов `Close()` безопасен.
- Все операции должны быть потокобезопасны при конкурентном доступе из нескольких горутин.

## API

```go
func NewTTLCache(ttl time.Duration, cleanupInterval time.Duration) *TTLCache
func (c *TTLCache) Set(key string, value string)
func (c *TTLCache) Get(key string) (string, bool)
func (c *TTLCache) Close()
```

## Ограничения

- Используйте только стандартную библиотеку Go; внешние зависимости запрещены.
- После `Close()` фоновая горутина должна завершиться.
- Решение должно компилироваться и запускаться командой `go run solution.go`.

## Критерии приёмки

- `Set` и `Get` корректно работают с существующими ключами.
- `Get` возвращает `false` для отсутствующих и просроченных записей.
- Фоновая горутина удаляет просроченные записи.
- `Close()` останавливает фоновую горутину без утечки; повторный вызов не вызывает панику.
- Конкурентные вызовы `Set` и `Get` не приводят к гонкам данных.
